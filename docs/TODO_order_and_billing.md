## A. להחיות את המסלול הקיים — חוסם

- [ ] **A1. להריץ את `supabase/migrations/0002_site.sql` בייצור.** *(גל בלבד)*
      להוסיף secret `SUPABASE_DB_URL` — חובה מחרוזת של ה-**session pooler**
      (`*.pooler.supabase.com`, פורט 5432, IPv4). החיבור הישיר
      `db.<ref>.supabase.co` הוא IPv6-only ו-runners של GitHub Actions נכשלים עליו.
      תווים מיוחדים בסיסמה — percent-encoding. ואז `workflow_dispatch` על
      "Apply Supabase migrations". חלופה: להדביק את הקובץ ב-SQL Editor.
- [ ] **A2. להגדיר `ADMIN_TOKEN`.** בלעדיו `/admin` חסום ו-`GET /api/inquiries`
      מחזיר `503 admin_disabled` — כלומר גם אחרי A1, פנייה שנשמרת לא נראית לאיש.
- [ ] **A3. התראה על פנייה חדשה.** אין בריפו שום קוד שליחת מייל — לא Resend, לא
      nodemailer, לא SMTP. להוסיף שליחה ל-`info@rmjewel.com` ב-`createInquiry`.
      דורש ספק + `RESEND_API_KEY` (או מקביל) כ-secret של ה-Worker, ואימות הדומיין
      `rmjewel.com` אצל הספק.
- [ ] **A4. מייל אישור ללקוחה** — מספר הזמנה, סיכום הפריט והמחיר. היום היא רואה
      מספר הזמנה על המסך בלבד; אם היא סוגרת את הטאב, אין לה שום אסמכתה.
- [ ] **A5. גיבוי כשה-API נכשל.** `submitOrder` מציג `checkoutError` וההזמנה אובדת.
      ליפול ל-`mailto:` עם כל הפרטים, כמו ב-`/contact`, כדי שלא תיעלם אף הזמנה.
